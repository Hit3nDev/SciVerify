    The library

    Every verdict is drawn from these 5,183 SciFact abstracts. Search them directly with the same BM25 index the verifier uses (no model involved).

      How well it works

      Recorded results on the SciFact dev set (300 claims), read live from experiments/results/. Nothing on this page is typed in by hand.

      How a claim is checked

      Four plain steps. Every one is visible in the result, so you can see why a verdict was reached and where it went wrong.

      1. 1

        Search

        BM25 keyword search ranks all 5,183 abstracts by word overlap with the claim. The right paper is in the top 10 for 93.6% of dev claims.

      2. 2

        Read

        A natural-language-inference model (bart-large-mnli) reads each of the top papers and decides whether it entails, contradicts or is neutral to the claim.

      3. 3

        Weigh

        Papers only count if the model is confident. Support only gives SUPPORTED; contradiction only gives CONTRADICTED; both give CONFLICTING; neither gives UNKNOWN.

      4. 4

        Show

        Every paper used is listed with its search score, the model's full probability split, and the sentences that best match the claim.

      Three judges

      Step 2 can be done by different models. The switcher in Verify picks one.

      • General judge (bart-large-mnli, 407M parameters): trained on everyday English inference, never saw a scientific claim. All the original results were measured with it.
      • Science-trained judge (MiniLM, 82M): the small model after fine-tuning on the 809 training claims and their annotated evidence (experiments/finetune_nli.py). The dev set was not used for training or model selection.
      • Small general judge (MiniLM, 82M): the same model before fine-tuning, so the effect of training alone is visible.

      Two honesty checks

      • Calibrated confidence. A model's probability is not automatically the chance it is right. One number (a temperature) is fitted on the training split so that "80%" means right about 80% of the time (experiments/calibrate.py). The verdict never changes; only the number does. Both raw and calibrated values are shown.
      • Opposite-claim check. The claim's opposite is built with a few readable rules (swap a direction word, or insert / remove "not") and verified too. A judge that supports both a claim and its opposite is reacting to words, not meaning, and the verdict is flagged as unreliable (verification/counterclaim.py).

      Verdicts

      Supported
      At least one retrieved paper confidently entails the claim and none contradicts it.
      Contradicted
      At least one paper confidently contradicts it and none supports it.
      Conflicting
      Papers disagree. The system reports the disagreement instead of picking a side.
      Unknown
      No paper gave confident evidence either way, or nothing relevant was found.

      Honest limits

      • It only knows 5,183 biomedical abstracts. Claims outside that area usually come back Unknown.
      • About 6 in 10 verdicts match the dataset's answer key on the dev set.
      • Confidence is the model's own probability, not a calibrated chance of being right.
      • The weak link is the judging model, not the search: it labels the key paper correctly 65.8% of the time.
      • The sentence analysis on each paper is a reading aid. The verdict always uses the whole abstract.

      Use it from code

      The same engine is a JSON API. Interactive docs are at /docs.

      curl -X POST http://localhost:8000/verify \
  -H "Content-Type: application/json" \
  -d '{"claim": "Monoclonal antibody targeting of N-cadherin inhibits metastasis.", "top_k": 3}'
